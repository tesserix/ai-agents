# Review planning preparation once with the final itinerary

Two concurrent production mobile requests on 2026-10-13 exceeded the synchronous planner deadlines after the grounding and budget fixes. Gateway timings included a 38-second request review with only 40 output tokens. The pipeline could make nine initial model calls: three for planning and three each for weather and entry preparation. The advisory workers already return every eligible provider record unchanged, regardless of model selection. Their recursive reviews frequently hit their 25-second deadlines and discarded available preparation information.

For three-option planning only, project current weather and entry records directly into preparation summaries. Preserve all source URLs, coverage gaps, missing traveller fields and verification states. Do not manufacture visa eligibility or forecasts. Retain the independent pre-execution review and final itinerary review. The final reviewer receives both preparation summaries and their complete provider evidence; a rejected final verdict still prevents any answer reaching the user. Standalone weather and entry requests retain their current specialist workflow.

This reduces initial model calls from nine to three without changing endpoint contracts, deadlines, storage, authentication, delegation or replica counts. Existing bounds remain: 40 evidence records, 40 KB review context, 64 KB worker reply, 80-second manager request and 95-second mobile request. Qualification uses two concurrent synthetic requests because two simultaneous mobile failures are the observed load; peak production RPS and p99 are not yet measured. No data volume or 12/36-month storage growth is introduced. Target remains completion within the current mobile deadline while preserving fail-closed final approval. Provider outages retain explicit unavailable preparation summaries.

An isolated lower-reasoning trial took 53 seconds versus 52 seconds for the existing configuration, so that tuning is not deployed. Increasing all timeouts was rejected because the public edge has a roughly 100-second limit. This change saves up to six model calls per plan with no new recurring infrastructure cost. Deployment uses a reviewed immutable manager image through GitOps; reverting that pin restores the old workflow without a schema migration.
